Part 0

Why Are We Even Here?

You've All Used a Chatbot

ChatGPT, Claude, Gemini...

You ask. It answers.

But what happens when you ask it to do something?

Start with shared experience. Everyone has used these tools. The key insight we're building toward: there's a ceiling.

The Chatbot Ceiling

You: Book me a table at a good Italian restaurant for tonight
ChatGPT: I can't make reservations directly, but here are some highly-rated Italian restaurants in your area:

1. Trattoria Roma - 4.7★
2. Bella Napoli - 4.5★

You can book via OpenTable or call them directly.

It gave you information. It didn't do the thing.

This is the fundamental limitation. The chatbot is helpful—it researched, it gave good info—but YOU still have to do the actual work.

What If It Could Actually Do It?

You: Book me a table at a good Italian restaurant for tonight, 7pm, 2 people
→ searching restaurants...
→ checking ratings and reviews...
→ querying OpenTable API...
→ found availability at Trattoria Roma...
→ making reservation...
Agent: Done! Table for 2 at Trattoria Roma, 7pm tonight.
Confirmation #12345. Dress code: smart casual.
I've added it to your calendar.
This is what an agent does. Notice the steps—it's not just answering, it's working through a multi-step process to actually complete the task.
That's an agent.
It doesn't just answer — it completes the task.
This is the core distinction we'll build on for the rest of the lecture.

The Key Distinction

Chatbots respond.
Agents pursue.

Chatbot

You drive.
It reacts to each input.

Agent

You give a goal.
It figures out the steps.

This is the mental model shift. With a chatbot, you're doing the planning. With an agent, you delegate the planning too.

What Makes Something "Agentic"?

From multi-agent systems literature:

  1. Autonomy — Makes decisions without approval at each step
  2. Goal-directedness — Works toward an objective, not just responding
  3. Reactivity — Responds to environment (tool results, errors)
  4. Proactivity — Takes initiative, doesn't wait to be told
  5. Persistence — Can work over time, across sessions

A chatbot might have #3.
An agent has all five.

These come from academic literature on agents—predates LLMs. The definitions still apply. A thermostat has #3 (reactive). An LLM agent should have all five.

Concrete Example: Research Task

Chatbot

You: What are the latest developments in quantum computing?
Bot: [Generates plausible-sounding summary from training data that's 18 months old]

Agent

You: Research latest quantum computing developments, write a 1-page summary with citations
→ I need recent info, searching arxiv...
→ Found 15 relevant papers...
→ Reading and synthesizing...
→ Key themes emerging...
Agent: Here's your summary based on 12 sources from the past 3 months...

The agent did the work, not just the answering.

Part 2

Why Agents? Why Now?

What Changed?

Agents weren't possible until recently because...

Requirement What Changed
Reasoning ability LLMs got good enough to plan multi-step sequences
Tool use Function calling became reliable (2023+)
Memory Context windows: 4K → 128K → 1M+ tokens
Cost 100x reduction makes iteration affordable
Ecosystem APIs, frameworks, standards matured
Each of these was a blocker. Even 2 years ago, you couldn't reliably get an LLM to call tools in the right format. Now it's routine.

The Capability Explosion

METR research on "task horizons":

2023 ~1 minute tasks
2024 ~1 hour tasks
2025 Multi-hour tasks

Doubling every ~7 months

This is from METR's research. "Task horizon" = how long a task can the model reliably complete. The growth is exponential.

What Agents Enable

Things that were impossible (or required dedicated software):

  • Coding: "Fix this bug across 50 files"
  • Research: "Analyze these 100 papers, find common themes"
  • Operations: "Monitor logs, alert me to anomalies"
  • Personal: "Plan my Japan trip, book everything"
  • Business: "Process invoices, update the spreadsheet"

Common thread: Multi-step tasks requiring judgment

Part 3

How Agents Actually Work

The Dirty Secret

Here's the thing:

LLMs can't actually do anything.

They're text-in, text-out machines. They can't:

  • Search the web
  • Run code
  • Send emails
  • Access databases
  • Make API calls

So how do agents work?

This is the key insight. Students often think LLMs have special powers. They don't. They generate text. That's it.

The Wrapper Program

Everything you see in ChatGPT is an application that wraps the LLM:

┌──────────────────────────────────────────────────────────┐
│                    WRAPPER PROGRAM                        │
│  ┌────────────────────────────────────────────────────┐  │
│  │              CONTEXT WINDOW                         │  │
│  │                                                     │  │
│  │  • System instructions                              │  │
│  │  • Memories / retrieved context                     │  │
│  │  • Tool definitions                                 │  │
│  │  • Conversation history                             │  │
│  │                                                     │  │
│  │  ─────────────────────────────────────────────────  │  │
│  │  → MODEL GENERATES NEXT TOKENS HERE →               │  │
│  └────────────────────────────────────────────────────┘  │
│                                                           │
│    Wrapper parses output, executes tools,                 │
│    injects results, loops until done                      │
└──────────────────────────────────────────────────────────┘
This diagram is the mental model for the whole course. Everything we learn is about what goes into that context window and how the wrapper interprets what comes out.

Tool Calling Is Just... Text

When an LLM "calls a function," it's generating structured text:

{
  "tool": "search_web",
  "arguments": {
    "query": "best italian restaurants seattle"
  }
}

The wrapper program:

  1. Parses this text
  2. Actually calls the API
  3. Gets the result
  4. Injects it back into the prompt
  5. Asks the LLM what to do next

The LLM has no special powers. It's just very good at generating the right text.

The Agent Loop

        ┌──────────────────────────────────────────┐
        │                                          │
        │   ┌─────────┐          ┌─────────┐      │
        │   │  THINK  │ ───────▶ │   ACT   │      │
        │   └─────────┘          └────┬────┘      │
        │        ▲                    │           │
        │        │                    ▼           │
        │        │              ┌─────────┐       │
        │        └───────────── │ OBSERVE │       │
        │                       └─────────┘       │
        │                                          │
        │            (repeat until done)           │
        └──────────────────────────────────────────┘

This is the ReAct pattern: Reasoning + Acting, interleaved.

Yao et al., 2022 — "ReAct: Synergizing Reasoning and Acting in Language Models"

ReAct is the foundation. Cite the paper. Students will implement this pattern from scratch for their weekend assignment.

Trace Through a Real Example

Task: "Who won more Grammy awards — Taylor Swift or Beyoncé?"

Thought: I need to find Grammy counts for both artists. Let me search.
Action: search("Taylor Swift total Grammy awards")
Observation: Taylor Swift has won 14 Grammy Awards as of 2024...

Thought: Got Taylor's count (14). Now I need Beyoncé's.
Action: search("Beyoncé total Grammy awards")
Observation: Beyoncé has won 32 Grammy Awards, the most by any artist...

Thought: Beyoncé (32) > Taylor Swift (14). I can answer now.
Action: finish("Beyoncé has won more Grammys (32) vs Taylor Swift (14).")
Walk through each step. Note how the reasoning traces let us SEE the model's logic—this is key for debugging and trust.

The Code Is Simpler Than You Think

def run_agent(query, tools, max_steps=10):
    history = []
    
    for step in range(max_steps):
        # Build prompt from current state
        prompt = build_prompt(query, history, tools)
        
        # Get LLM's response
        response = llm.complete(prompt)
        
        # Parse for tool calls
        action = parse_action(response)
        
        if action.tool == "finish":
            return action.argument
        
        # Execute tool and observe result
        result = execute_tool(action.tool, action.argument)
        history.append((action, result))
    
    return "Max steps reached"

That's it. Everything else is details.

This is the skeleton of their weekend assignment. Emphasize how simple the core loop is.
By end of Week 1, you will have built a working ReAct agent from scratch.

Not using frameworks or tutorials

  • Why it sometimes fails
